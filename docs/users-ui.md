# Административная страница «Пользователи»

Откройте `/users` через пункт «Пользователи» в навигации администратора.
Участнику пункт не показывается; прямой переход показывает отказ без запросов
Users API. Сервер дополнительно проверяет admin на всех Users/ACL endpoints.

Форма создаёт активного **member** с логином и паролем. Назначения роли нет.
Логин: 3–64 ASCII-символа, буквы, цифры, `_`, `-`, `.`. Пароль: минимум
12 Unicode-символов, максимум 1024 байта UTF-8. После отправки пароль очищается;
при ошибке его нужно ввести заново. Пароль не попадает в React state,
TanStack Mutation variables, список, уведомления или логи приложения.

После создания список инвалидируется через TanStack Query. Поскольку Go
сортирует пользователей по возрастанию даты создания, интерфейс открывает
последнюю страницу и панель ACL нового участника. У нового пользователя нет
разрешений на документы и нет старых диалогов.

В панели «Доступ к документам» выдайте доступ только к выбранным документам.
Кнопка «Отозвать доступ» снимает разрешение. Доступ администраторов ко всем
документам задаёт сервер; для них панель выдачи ACL не предлагается.
У неактивного участника можно отозвать разрешение, но нельзя выдать новое.
Списки пользователей и документов имеют пагинацию. При проверке ACL одного
документа клиент читает все страницы до нахождения пользователя или конца списка;
ошибка загрузки не считается отсутствием разрешения.

## Проверенный контракт Go

Источники: `internal/transport/http/handlers/users.go`, `common.go`,
`documents.go`, `internal/service/users.go`, `password.go`,
`document_access.go`, `internal/transport/http/router.go`.

| Endpoint | Данные |
| --- | --- |
| GET `/api/v1/users?limit=20&offset=0` | `{items: [{id, username, role, is_active}], total}` |
| POST `/api/v1/users` | `{username, password}` → 201, `{id, username, role, is_active}` |
| GET `/api/v1/documents/{id}/access?limit=100&offset=0` | `{items: [{id, username, role, is_active}], total}` |
| POST `/api/v1/documents/{id}/access` | `{user_id}` → 201, `{id, document_id, user_id, granted_by, created_at}` |
| DELETE `/api/v1/documents/{id}/access/{userId}` | 204 |

Используется общий API client: same-origin session cookies и `X-CSRF-Token`
из `ai_csrf` / `__Host-ai_csrf` на POST/DELETE. Пароль, роль, сессия и CSRF
не сохраняются в localStorage. Ошибки 400/409 имеют сообщения для создания
пользователя, 403 сообщает об отсутствии доступа или проблеме CSRF; 401
обрабатывается существующим механизмом завершения сессии. Текст ошибок сервера
не показывается.

## Проверка

Из `frontend`: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
Тесты покрывают RBAC навигации/прямого маршрута, реальные поля, создание,
пагинацию после создания, очистку пароля, валидацию, 400/403/409/500, cookie/CSRF,
выдачу/отзыв ACL и чтение нескольких страниц ACL.

Для повторной проверки реального Docker используется
`python scripts/verify-users-access.py`. Скрипт читает admin из локального
`.env`, а созданного через браузер demo-member — из игнорируемого Git файла
`.local-integration/users-page/credentials.json`. Он не создаёт пользователей
и не меняет ACL: проверяет вход, RBAC, запрет назначения admin, CSRF/Origin,
конфликт логина, пустую историю, чтение разрешённого документа и отказ для
остальных. Меняются только тестовые сессии входа/выхода. Результат без паролей
сохраняется рядом в `verification.json`.

Демонстрационный member имеет доступ только к «DEMO Регламент учебного
оборудования»; доступ к «DEMO Регламент учебного архива» был выдан и отозван
через браузер. Для другой конфигурации передайте `--credentials` и
`--allowed-title`. Не выводите содержимое файла credentials в общий лог.
