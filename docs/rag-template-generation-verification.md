# RAG Generation: незаполненные шаблоны — 24 октября 2026

## Причина

Статус выбирала Qwen. Старый системный промпт задавал только общие условия
«Если вопрос неоднозначен…» и «Если доказательств недостаточно…», но не отличал
известную структуру и явно пустое поле от отсутствия доказательств.
Модель трактовала вопрос о составе как обязательный запрос конкретных ФИО,
а пустое назначение контролирующего лица — как повод запросить сведения
у пользователя. Она распознавала роли, но отказывалась сообщить известную часть.

Это подтверждено сырыми JSON: в clarification_question модель сама перечисляла
известные роли, после чего просила предоставить ФИО/должности или уточнить
проект. Для контроля просила заполнить пропуск или назвать контролирующее лицо.
В остальных отказах raw status уже был insufficient_information.

Проверенный путь данных:

1. `app/rag/prompts.py::messages_for` сериализует весь валидированный request
   в `untrusted_request_data`, сохраняя порядок sources, UUID, табуляции,
   подчёркивания и пустые значения метаданных. Отбора/склейки/усечения нет.
2. `app/llm/client.py` передаёт эти сообщения OpenAI-совместимому API и возвращает
   `choices[0].message.content` при finish_reason=stop. Статусы RAG не меняет.
3. `app/rag/generator.py` разбирает JSON, валидирует состояние и принадлежность
   UUID входному набору, затем возвращает результат. При непустых sources
   никакой замены статуса на insufficient_information нет. При невалидном
   ответе возвращается HTTP 502 / llm_invalid_response.
4. Единственный самостоятельный insufficient_information в генераторе —
   sources=[], без обращения к модели. В проверенных запросах sources непуст.
5. Схема находится в `app/schemas/rag.py`; `app/rag/schemas.py` в проекте нет.
   Валидатор проверяет форму состояния, а не наличие ФИО в тексте ответа.

## Изменения

- `ai-service/app/rag/prompts.py`: общие правила интерпретации шаблонов,
  связанных табличных строк, пустых полей, подписей и примечаний; границы трёх
  статусов; нейтральное уточнение без заполнения неизвестных значений догадками.
- `ai-service/app/schemas/rag.py`: уточнено только описание статуса в схеме.
  Поля DTO, перечисление статусов и валидаторы сохранены.
- `ai-service/tests/test_rag_templates.py`: 15 контрактных случаев с mock LLM.
  Проверяются частичные ответы, пустые реквизиты, неоднозначность, отсутствие
  доказательств, передача всех строк/UUID, разделение правил и недоверенных
  данных, отсутствие логирования, отклонение чужих UUID и невалидных состояний.
- `ai-service/tests/test_rag.py`: зафиксированы temperature=0 и max_tokens=4096
  в существующей проверке HTTP-адаптера.
- `ai-service/scripts/evaluate_template_rag.py`: отдельный локальный инструмент
  реальных повторных вызовов Qwen и воспроизведения raw через Python-валидацию.
- `docs/rag-generation-contract.md` и этот отчёт: семантика и воспроизводимость.

Фиксированных ответов и ветвлений по вопросам в рабочем генераторе нет.
Benchmark содержит вопросы и проверки только в отдельном оценочном скрипте.
`generator.py`, `llm/client.py`, ingestion, Go, PostgreSQL и действующий сервис
не менялись.
Проверки UUID/JSON/состояния, лимиты, защита от инструкций из sources/history,
авторизация служебным токеном и ограничения endpoint сохранены.

## Реальная модель и контекст

Проверен существующий endpoint: GET /v1/models → HTTP 200, доступна
`qwen3.6-35b-a3b`. Использованы существующие настройки LLM из локального .env.
Конфигурация, модель и контейнеры не заменялись; веса не загружались.

рабочая группа; название и бизнес-документ не исправлялись.

Пять исходных вопросов используют ровно [10–14], [10–14], [16], [17], [19].
Это проверка production-функций generate → messages_for → LLMClient → Qwen

Параметры каждого запроса до/после одинаковы: temperature=0, max_tokens=4096,

параметры семплирования и seed адаптер не задаёт. Каждый сценарий — пять
отдельных вызовов модели, без автоматических повторов при ошибке.

Raw JSON каждого вызова затем повторно передаётся в рабочий generate через
replay-клиент, возвращающий именно полученную строку, без нового инференса.

Проверяются допустимость UUID, необходимые роли/обязанности и незаполненность

Основное сравнение: 25 реальных вызовов с исходным промптом и 60 с итоговым.

ровно пять независимых вызовов; статусы указаны полностью.

## Воспроизведение и приватность

Пример для текущего приватного локального экспорта, из корня репозитория:

```powershell
& ai-service/.venv/Scripts/python.exe ai-service/scripts/evaluate_template_rag.py --sources .local-integration/rag-template-eval/sources.json --output .local-integration/rag-template-eval/accepted.json --env-file .env
```

Для сравнения до изменения используйте сохранённый исходный prompts.py через
`--prompt-file` и `--core-only`. `--case ambiguous_deadline` позволяет отдельно
повторить выбранный сценарий. Меньше пяти повторов скрипт не допускает.

Консоль скрипта выводит только условные имена сценариев, количества статусов,
проверок и совпадений при валидации. Полный контекст, вопросы и raw не добавлены
в логи сервиса. Приватные локальные файлы `sources.json`, `before.json`,
`accepted.json` находятся в игнорируемом `.local-integration/rag-template-eval/`;
их нельзя публиковать как общедоступные артефакты стенда. Этот отчёт не содержит
полного документа, контекста или сырых ответов с внутренними данными.

## Ограничения

- Пять повторов на одном документе и модели показывают устойчивость на этой
  выборке, но не гарантируют поведение на других шаблонах. Даже temperature=0
  не обеспечивает побайтово одинаковый текст на текущем inference backend.
- UUID-валидация проверяет принадлежность источника, а не истинность каждого
  утверждения. Mock-тесты проверяют контракт; лексические benchmark-проверки
  также требуют смысловой проверки ответов человеком.
- Qwen иногда повторяет настоящее название документа или номер пункта в тексте
  вопреки инструкции отображать ссылки отдельно. Такие повторы не означают
  выдуманных источников, но ограничение оформления остаётся. В дополнительном
  ответе о контроле модель неудачно называет примечание 7 «примечанием к пункту
  7»; назначения из него не выдумывает. Точность таких текстовых отсылок
  не обеспечивается проверкой UUID.
- Текущие табличные строки остаются раздельными chunks. Переработка ingestion
  больших таблиц и недостаточных метаданных — отдельная задача; здесь она
  не выполнялась. Существующий DTO не расширен.
- Новая версия промпта проверена локальным Python-процессом; работающий Docker
  сервис продолжает использовать исходный код. Commit, push и deploy не выполнялись.
