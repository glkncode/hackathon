Проверка проведена 24 октября 2026 года в `D:\Projects\hackathon`, на локальном Docker Compose и настоящем React production UI. Основной сценарий — [final-demo-script.md](final-demo-script.md), рассчитанный примерно на 4:40 с подготовленным черновиком.

**Основной демонстрационный сценарий готов при успешном preflight. Расширенный RAG имеет известный пропуск: 14 из 15 контрольных вопросов прошли, один вопрос по модулю ответственных за ДОУ не находит нужный фрагмент.** Это ограничение не относится к трём вопросам основного показа и не скрыто из результатов. Автоматический preflight проверяет эксплуатационную готовность, а не доказывает полноту ответов на произвольные вопросы.

Материалы организаторов учебные. Инструкция прямо помечена как не действующий документ; п.12.11 указывает начало применения **1 ноября 2026 года**, за исключением отдельных сроков из приказа. На дату проверки **24 октября** её нельзя представлять уже действующим нормативным актом. Генератор создаёт проекты; не выполняет реальное визирование, подпись, ЭП или регистрацию.

## Запуск проверки

Из корня проекта, при работающем Docker Desktop:

```powershell
pwsh -NoProfile -File .\scripts\demo-preflight.ps1 `
  -JsonReport .\.local-integration\final-demo\preflight.json
```

Проверенный запуск — `pwsh`. Синтаксис рассчитан также на Windows PowerShell 5.1, однако его запуск на этой машине заблокирован системной execution policy; политика не менялась и не обходилась. Нужны Docker Compose и доступ к локальному приложению; Python на хосте для preflight не требуется. Если локальный порт изменён, передать `-BaseUrl http://localhost:<порт>` с разрешённым сервером Origin.

Без параметра `-Credential` используется сохранённая локальная synthetic-учётная запись. Альтернатива — `-Credential (Get-Credential -UserName 'demo-jury-20261024')`. Пароль не передавать в аргументах командной строки и не включать в отчёт. Файл `.local-integration/final-demo/credentials.json` содержит локальные пароли, игнорируется Git и не предназначен для отправки жюри; его ACL на проверенной машине ограничен текущим пользователем и SYSTEM.

Финальный запуск в 20:55 МСК: **16 PASS / 0 FAIL**, exit **0**, **24,379 с**. Все основные контейнеры оставлены healthy. Результат: строки PASS/FAIL с конкретным способом исправления, JSON без секретов, exit code 0 при всех PASS и 1 при наличии FAIL. Preflight не запускает/не останавливает контейнеры, не мигрирует схему, не загружает документы, не изменяет ACL и не создаёт черновики. Он создаёт и отзывает только служебную сессию входа, выполняет запросы чтения, контрольный embedding, контрольную генерацию Qwen и POST поиска. SQL выполняется в `BEGIN READ ONLY`. Проверка записи в файловое хранилище — проверка прав каталога без создания файла; фактическая запись отдельно доказана успешной генерацией.

Проверяются четыре healthy-контейнера, API/Nginx/React shell, PG17 и pgvector, 17 таблиц, named volumes и совпадение выбранного PG-volume с Compose, включённые ingestion/RAG/semantic flags, Python, конечный 384-мерный нормализованный E5-вектор, отдельная Qwen с настоящим JSON-ответом, manifest, индексы 13 активных версий именно с загруженным model/revision/format, storage, member login/CSRF, точный набор demo ACL, SHA-256 всех 13 скачанных оригиналов, семь доступных v2 и два готовых reserve-черновика.

Если FAIL, исправить указанную причину и повторить проверку. Для Qwen проверить отдельный inference и сеть; для незавершённого индекса дождаться worker и прочитать ошибки очереди. Не заменять исправление повторной загрузкой тех же документов и не очищать volumes. При 429 дождаться указанного сервером Retry-After.

## Безопасность и отказоустойчивость

Публичные API проверки подтвердили 404 для документа/download без ACL, чужого черновика, чужого generated UUID/metadata/download; даже admin не читает чужие личные черновики. POST без CSRF даёт 403; anonymous list — 401. Отзыв доступа synthetic-пользователя скрывает документ из поиска, редактирует выдаваемую историю прежнего ответа и запрещает download. Отзыв доступа к источнику шаблона запрещает чтение черновика и готового результата. Все временно отозванные demo-права восстановлены в `finally`.

Отдельная Qwen проверена реальным контрольным завершением. В изолированном AI-процессе с недоступным inference получен **503 `llm_unavailable`**; удалённая машина Qwen не останавливалась и её инфраструктура не менялась. Обработка этой ошибки Go с переходом к поисковому режиму проверена существующим `TestChatRAGResponsesFallbackAndIdempotency/unavailable`; это тест контракта с имитацией отказа, а не отключение удалённой Qwen в основном Compose.

При фактической остановке `ai-service` основной Go API продолжил выдавать FTS-результаты; Chat вернул `mode=search` с источниками, готовый DOCX скачался побайтно идентично. Новая генерация вернула **502**; после запуска Python повторная попытка сформировала валидный DOCX. Полная последовательность проверок во время простоя заняла **32,094 с**: fallback может ждать отказа обращения к Python, это не обещание мгновенного ответа.

Полный restart четырёх основных сервисов до всех healthy и успешного E5-запроса занял **15,395 с**. До и после совпали число строк и MD5 от упорядоченного содержимого **13 таблиц**: документы/версии/ACL/chunks, индексы/semantic chunks/windows, шаблоны/черновики/результаты, chat sessions/messages/sources. Существующая сессия осталась действительна, ответы черновика сохранились, прежний generated DOCX совпал по SHA-256 и байтам. Это проверка сохранности, а не резервная копия. Свидетельства — `.local-integration/final-demo/resilience.json`. Все named volumes сохранены. Холодная установка/скачивание моделей и запуск удалённой Qwen в этот замер не входят.

## Перед выходом на защиту

1. Открыть Docker Desktop заранее, подключить питание и сеть до отдельной Qwen. Если сервисы выключены, воспользоваться существующим `scripts/start-local.ps1`; дождаться preflight, а не только сообщения о запуске.
2. Один раз выполнить preflight и убедиться в exit 0 и всех PASS. Если готовый reserve-проект вручную испорчен, исправить его через React; setup не затирает пользовательские изменения.
3. Взять пароль demo-пользователя из локального credentials-файла вне проектора. Оставить одну открытую сессию; не выполнять многократные логины. При 429 дождаться Retry-After. Не выключать limiter и не обходить его restart.
4. Открыть `final-demo-script.md`, вкладки чата, reserve ИС и готового результата. Проверить browser zoom, читаемость и нужный экран; убрать credentials-файл и служебные логи с проектора.
5. Открыть `browser-is.docx` и `browser-working-group.docx` в целевом Word/LibreOffice; проверить шрифты, переносы и таблицу. Не менять исходный модуль. При необходимости поправить только synthetic-значения проекта и повторить генерацию.
6. Держать локальные DOCX и сохранённый диалог как явно обозначенный резерв. Не выдавать сохранённый результат за новую работающую генерацию при отказе сервиса.
7. Проговорить 4:40 по сценарию, включая фразу об учебном статусе, начале применения 1 ноября и отсутствии реальной подписи/регистрации. Не включать диагностический FAIL по ответственным за ДОУ в основной показ; при вопросе жюри честно показать ограничение и исходный документ.
