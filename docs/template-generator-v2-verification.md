# Template Generator 2.0 — итоговый отчёт

Дата: 24.10.2026. Рабочая копия: `D:\Projects\hackathon`. Локальный Compose оставлен работающим. Реализован backend Profile 2; React Wizard не добавлялся. Финальные профили: `profile_version=2`, `revision=2.0.2`, `rules_version=2026-10-24.3`, `engine_version=docx-profile/2.0.0`.

## 1. Аудит

Найдены и прочитаны **все десять** исходников в `data/demo`: PDF Инструкции по ДОУ, Матрица обязательного визирования, Методические рекомендации и семь модульных DOCX. Отсутствующих файлов нет. Из DOCX извлечены параграфы/таблицы/строки, из PDF — текст по страницам. Воспроизводимый экстракт и SHA находятся в `.local-integration/template-v2-audit`, скрипт — `scripts/audit_template_sources.py`.

Таблица расхождений с v1 и ссылки на положения: `docs/template-generator-v2-audit.md`. Ключевое расхождение: v1 технически заполнял файл, сохраняя утверждение исходного модуля, пометку и пояснения. V2 удаляет именно эти элементы по SHA и точным якорям, сохраняя дату/номер/ЭП и постоянные формулировки. Исходники не записываются; SHA всех семи сравнивается в тестах и E2E.

Факты, ограничивающие выводы: PDF явно назван учебным примером, а не действующим документом; в нём указано начало применения 01.11.2026. В методических рекомендациях п.4.2 пропущен номер 2, он не восстанавливался предположением. В оригинале ИС есть несогласованные кавычки; исправлен только закреплённый фрагмент. Оригинал комитета содержит ЭП без текстовой подписи. Приложение к локальному документу и акт передачи не входят в модули. Приоритет нормативных источников и официальная актуальность автоматически не определяются.

## 2. Архитектура и обратная совместимость

Python: отдельная строгая модель профиля, ограниченный декларативный rules engine и структурный renderer. При регистрации проверяются операторы, типы сравнений, ссылки полей, циклы, глубина/размер конфигурации, источник и XML-якоря. При render выполняются замены по runs, условные фрагменты/диапазоны, клонирование строк, точечная перенумерация, cleanup и проверка результата. Нет eval/exec или LLM.

Go: прежние сервис и endpoints расширены необязательным `profile`. V2 валидация, вопросы, progress и генерация используют один Python rules engine; Go проверяет входные типы, управляет ACL/revision/storage и транзакцией. Миграция 00010 добавляет nullable профиль и снимок результата, 00011 закрывает SQL NULL для неполного envelope v2; миграции 00001–00009 не менялись. Значения, полный профиль и отчёт конкретной revision сохраняются вместе с метаданными файла. Последующее изменение черновика не переписывает старый результат.

Старый массив `working-group.json` сохранён без изменений. Регистрации v1 продолжают использовать прежний renderer и прежние поля, включая утверждение модуля. Никакой автоматической смены смысла старых ответов нет. Все предыдущие endpoints и поля validation остаются. Новые профили регистрируются отдельными записями, исходная document_version_id закреплена. Подробный контракт — `docs/template-generator-v2.md`.

## 4. Что получилось в реальных DOCX

Для всех семи удалены таблица утверждения модуля, маркер, примечания, общие правила и связанные пустые разрывы. Остальные ZIP-части, включая styles, numbering, headers/footers, PAGE, relationships и media, побайтно совпадают с оригиналом. Защищённые параграфы регистрации и ЭП совпадают по XML; секции сохраняются. Линии заменяемых полей и номера примечаний устранены. Предусмотренная формой линия будущей подписи сохранена.

Рабочая группа: заполнены тема/цель, руководитель/секретарь/члены, deadline/actions/result/addressee, termination/controller/signer. Тема повторяется из одного поля, строки членов реально клонируются; постоянные пп.3–4 сохранены.

Комитет: одинаковые названия в заголовке, преамбуле, п.1; согласованы «проекту/проектам», «проекта/проектов», «реализуемого/реализуемых». При отключении отмены удалены союз и фрагмент заголовка, п.2 целиком; контроль стал п.2. При включении заполнены реквизиты прежнего распоряжения, заголовок использует «об отмене распоряжения», п.2 — «Отменить распоряжение», контроль остаётся п.3. Состав — отдельные строки, ЭП не заменена текстовой подписью.

ИС: заполнены названия, readiness_document/date/number, development_document/date/number, change_kind, commissioning_date, customer/purpose/it_department/responsible/signer. Сокращённое имя одинаково в пяти местах. Ошибка более ранней даты блокирует generate; явное подтверждение исключения без основания недостаточно. Утверждение эксплуатационной документации не объявляется доказанным.

Локальный документ: вид/имя согласованы в заголовке и п.1; для «Инструкции» проверены формы «Об утверждении … Инструкции» и «Утвердить Инструкцию». Ссылка на приложение сохранена с предупреждением об отсутствии физического вложения. При отключении отмены контроль 5→4.

Ответственные за ДОУ: связаны подразделения и конкретные работники, сохранены обязанности и получатель уведомлений/координатор. При отключении отмены контроль 6→5. Подтверждение согласия не имитируется.

Передача: заполнены основание, стороны, предмет, представитель, срок/основание срока; оборот «от …» отсутствует при отключении. Проверен вариант «оставляю за собой». Визуально сохранена должность Председателя из исходного модуля. Акт физически не включается.

Аудит: согласовано число процессов, заполнены даты, руководитель/аудиторы, доступ, срок/адресат отчёта, владелец/срок плана, контроль/подписант. Независимость не выводится из неизвестных обязанностей.

При визуальной проверке исправлены переносы таблиц: cantSplit добавляется только по профилю, заголовок повторяется через tblHeader. Проверены **14 PDF / 22 страницы**, изображения просмотрены. Экспорт выполнен LibreOffice Writer 25.2 в отдельном временном QA-контейнере, со шрифтами Liberation/DejaVu. Microsoft Word не запускался. При очень длинных пользовательских значениях и иных установленных шрифтах нужен дополнительный просмотр на целевой машине.

## 7. Безопасность и сохранность

Session auth, CSRF, RBAC, ACL и ownership не заменялись. Admin не получает доступ к чужим личным черновикам/результатам. Перед генерацией и после render выполняются проверки доступа; тест отзыва ACL во время v2 render присутствует. Уже готовый результат скачивается с повторной проверкой ACL, без зависимости от Python. Источник закреплён UUID версии и SHA; профиль/правила/engine/значения/отчёт сохраняются. FOR UPDATE, CAS и unique(draft_id,draft_revision) сохранены. Ошибка подтверждения COMMIT по-прежнему не приводит к удалению возможно зафиксированного файла.

Сохранились защита storage paths, лимиты ZIP/распаковки/XML, запреты XXE, traversal, macros, embedded executable content и внешних relationships. Профили не исполняют код. Личные значения не добавлялись в логи. Миграция на основной БД была только аддитивной. Пользовательские документы, история, черновики, результаты и embedding volume не удалялись. Не выполнялись down -v, volume prune, DROP DATABASE, commit/push/deploy или изменения VPS/CI/CD.

## 9. Что осталось

Обязательного незавершённого backend-механизма из этого этапа нет. Для подключения React Wizard нужно использовать conditional metadata, next_question, видимые/обязательные ключи и показать все категории отчёта; `ready` означает возможность сформировать файл проекта, а не готовность подписать документ без дальнейших процедур.

Для конкретного документа обязательны человеческие действия из отчёта: актуальность модуля, полномочия, смысловая/языковая проверка, требуемые согласия и независимость, основания исключений, реальные приложения, лингвистическая экспертиза и установленный маршрут. Перед защитой полезны согласованные демонстрационные данные, целевые шрифты и просмотр на компьютере демонстрации.

Сознательно вне этапа: реальное визирование и ЭП, ИИС ДО, регистрационные номера/даты, универсальное преобразование неизвестного DOCX, автоматическая юридическая квалификация, физическое объединение приложений, новый RAG/semantic, OCR/SSO, WYSIWYG и новая инфраструктура.
