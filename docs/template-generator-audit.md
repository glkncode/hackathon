# Аудит перед реализацией DOCX Template Generator

Дата: 24 октября 2026.

Исходные миграции 00001–00008. Рабочее дерево содержит ранее сделанные изменения semantic/RAG/Docker; они сохраняются. Сервис Python уже имеет `/internal/v1/templates/inspect` и `/render` в `app/api/templates.py` (файла templates/routes.py нет). Оба защищены общим PrivateAPIMiddleware и X-Service-Token; используется semaphore template_slots. Существующий engine проверяет ZIP/XML, sandbox Jinja и допускает только простые строковые placeholders. Циклы, выражения, макросы, внешние relationships и исполняемые Word fields запрещены.

Реальный файл находится в data/demo, имя содержит Unicode combining characters. Он не содержит Jinja placeholders. Обнаружены 48 XML-параграфов, четыре таблицы: утверждение, герб, состав, подписант/визуализация ЭП. Поля разбиты на Word runs. В footer есть безопасное поле PAGE, которое старый engine также запрещает. Документ содержит линии заполнения, примечания [1]–[8], дату/номер и визуализацию ЭП с пометкой НЕ УДАЛЯТЬ.

Решение: расширить тот же engine параметром schema с явными binding {part, paragraph, match}, проверяемыми на неизменённом оригинале. Привязка соответствует только одной версии DOCX. Замены происходят в w:t с сохранением w:pPr/w:rPr; другие ZIP parts копируются без изменений. Данные не интерпретируются как Jinja. Разрешить только статические PAGE/NUMPAGES, без выполнения полей. Person list отображается строками в ячейке таблицы. Автоматический анализ сохраняется для простых placeholders; произвольные линии автоматически не распознаются.

Профиль working-group.json описывает 14 полей, включая утверждающее лицо, дату утверждения и организацию. Тема связана с двумя местами. Регистрационные дата/номер и блок ЭП сохраняются. Факсимиле подписи не создаётся. Общая логика Go не знает конкретных ключей рабочей группы.

Go уже хранит версии отдельно от documents, использует UUID storage_key, os.Root, ограничение размера, Sync и SHA-256. Файлы остаются на volume documents_data. Переиспользуются DocumentStorage, DocumentAuthorization, Documents.GetVersionByID, общий aiclient HTTP transport, middleware auth/CSRF/RBAC. ACL принадлежит исходному документу и применяется ко всем его версиям. Администратор имеет доступ к источникам, но ownership черновиков проверяется отдельно.

Добавляются три таблицы: неизменяемый опубликованный профиль шаблона (кроме enabled), пользовательский черновик с revision, самостоятельный результат с уникальностью (draft_id, draft_revision). Новый профиль/версия публикуется отдельной регистрацией. Черновик закреплён за профилем и исходной версией. Генерация использует транзакционную блокировку строки черновика, CAS revision, уникальность результата, ограниченный semaphore и повторную ACL-проверку после Python. Файл публикуется через метаданные только после успешной записи; при ошибке транзакции удаляется.
